# 运行控制与隐私边界

## 环境与范围

需要 Node.js 22.13+（内置 SQLite）、Python 3.9+、Git、POSIX `ps` 和 `lsof`。macOS 本机验证，Linux 跑仓库 CI；Windows 尚未支持。启用 Codex 对话目录另需 `sqlite3` CLI。

`.subboss/config.json` 保存 `projectRoot`、`port` 和 `includeCodexCatalog`。启动脚本将配置转换为环境变量；直接运行 `server.mjs` 时自行设置环境。`SUBBOSS_PROJECT_ROOT`、`SUBBOSS_DASHBOARD_PORT` 可覆盖默认值；测试使用独立 `SUBBOSS_RUNTIME_DB` 和 `SUBBOSS_CODEX_DB`。

默认 4317，仅绑定 127.0.0.1，不提供远程访问或多用户认证。不要通过反向代理公开此进程控制器。启动/停止看板用 `scripts/start_dashboard.sh` 和 `scripts/stop_dashboard.sh`；看板停止后业务监督进程保持运行，下次打开后继续管理。电脑重启后不自动恢复项目。

## 发现服务

扫描器跳过隐藏目录、依赖目录、生成目录和目录符号链接，有限度读取配置与源文件，不读取 `.env`。可识别常见 Next.js/Vite/Vinext/Astro/Nuxt/Hexo 开发脚本、已有静态网页、部分 FastAPI、Node HTTP、Remotion 和固定版本 HyperFrames 项目。

只直接运行已安装的工具，不执行任意 npm 生命周期钩子，不自动下载、安装、构建、迁移、填充数据或发布。复杂命令链保留为不可启动并解释原因。HyperFrames 只使用项目固定版本或已存在的精确缓存，关闭自动安装和更新。

数据库标签来自依赖和代码：例如 SQLite、PostgreSQL、MySQL、Redis 或浏览器存储。标签不证明实际连接、环境可用或数据正确。

## 所有权与安全

- 启动前查端口和监听进程；已占用时不抢占。
- 用独立监督进程、随机标识、进程组与持久化记录验证所有权；不能仅凭 PID 或端口杀进程。
- 请求只接受本机 Host 和同源来源；运行写接口使用随机 token，追踪写接口要求自定义请求头与 JSON。
- 静态资源使用白名单，不能读取服务端源码、状态、SQLite、日志或任意路径。
- 不提供任意 shell/命令执行接口。扫描出的命令也应来自可信项目；启动项目代码本身仍会产生该项目的正常副作用。
- 日志有大小上限并尝试遮蔽常见密钥模式，但遮蔽不是保密保证。不要公开日志或运行数据库。

## Codex 可选关联

默认禁用。显式启用后仅以 SQLite 只读方式查询本机对话标题、预览摘要、目录与归档标记；不读取正文文件、不改 Codex 数据库。未同步/其他设备对话不在覆盖内，数据库结构不兼容时报告不可用，不影响看板。它依赖本机内部元数据结构，未来版本可能需要适配。

`codex://threads/<UUID>` 指向已关联原对话，实际跳转依赖安装的 Codex 客户端和浏览器许可。不要通过替代通道绕过自动化浏览器的协议限制。

## 排查

- 端口冲突：改 `.subboss/config.json` 的 `port`，再启动；不要杀未知进程。
- 无法判定端口归属：确认安装 `lsof`；控制器应拒绝危险操作。
- 服务启动失败：查看该服务末尾日志，区别进程存活与 HTTP 就绪。
- 依赖缺失：回到项目按其规范处理，不在控制器中偷偷安装。
- 看板崩溃留下锁：确认没有进行中的启停命令后，移除 `.subboss/service.lock`；不要移除运行数据库来“修复”仍在运行的服务。
- 对话目录不可用：检查开关、sqlite3 和本机元数据兼容性；保留现有任务。
