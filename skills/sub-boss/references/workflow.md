# 从零搭建到持续管理

## 建立管理边界

把总控台作为独立目录，业务项目保持原状。总控目录内放管理说明、盘点结果、网页和控制器。先限定一个明确的项目根目录；只有用户点名其他目录时才登记扩展范围。创建 Skill 不等于授权扫描整台电脑。

## 盘点事实

先用扫描器读取一级项目目录，再逐个补读状态文件和关键证据。检查 Git 时区分独立仓库与上级仓库；文件改动数不是完成度。README 描述的是意图，发布配置是配置，已提交代码是提交证据，均不代表线上验收。

扫描器最多读取状态文件前 64 KiB，不读取 `.env`，不执行项目脚本或 Git 钩子。它只生成保守的待核实条目，不推断百分比、不判定验收。缺少状态文件写“未维护”，不要判定项目没有工作。

## 形成老板可用的事项

按“一个明确的交付或决策”拆分事项。将已做内容放 `progress`，剩余风险放 `remaining`，具体动作放 `next`。使用明确日期与负责人，缺失时写待安排。保持事项 ID；不要因为标题变化生成新 ID。

优先顺序：交付阻塞、等待决策、需要验证，然后常规推进。优先事项最多 3 条。先应用用户动作，已结束、无需追踪和延期未到的事项不参加排序。未归档对话不能证明尚未完成，归档对话不能自动恢复续办。

汇报格式：

1. 总体判断：正常 / 有风险 / 需要拍板。
2. 项目表：项目、阶段、进度、阻塞、下一步、需要决策。
3. 最多 3 条优先事项。
4. 影响交付的风险与依赖。
5. 谁做什么、在明确日期检查什么结果。

## 建立可操作界面

保留两种视图：工作看板负责事项与判断，项目启动台负责本地服务。事项详情保留完整上下文、六类证据和用户追踪动作。提供搜索、分类、筛选、列表/看板切换。中文使用系统无衬线字体，布局使用 Flex/Grid。模板包含四种主题与减弱动态效果支持；不需要外部字体、图像或 CDN。

保留关闭状态的原始内容；按钮操作只更新独立追踪文件。当前日报更新不能抹去历史动作。刷新网页只读取最新快照；重新扫描项目需明确触发。

## 增加本地运行控制

先读配置识别技术栈和数据库类型，再用允许的启动模式生成服务条目。一个项目可以有多个服务。显示端口、地址、命令来源、依赖、是否支持与原因。启动前检查端口；外部进程不可被停止或重启。

使用独立监督进程管理业务服务，避免关闭网页或重启总控台导致失控。运行目录和历史存 SQLite，日志有上限。默认仅监听本机；原项目启动代码仍可能访问网络、数据库或写缓存，不对不可信仓库执行启动。

## 验证和日常刷新

对界面进行实际浏览器检查；对控制器使用临时项目做完整启停；对权限做跨源拒绝、静态源码拒绝等测试。不能用“页面打开了”替代业务验收。

日常刷新先保存用户操作文件散列，补读新的证据，更新日报和明确的证据日期，再检查散列、数据与页面一致。过期证据保留原日期，不能凭新汇总时间冒充重新验证。定时任务应另行按用户要求建立。
